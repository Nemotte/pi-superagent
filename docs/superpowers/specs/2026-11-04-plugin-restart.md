# 插件内重启后台服务

用户明确要求插件支持重启，不应退回手写终端脚本。沿用文档化后直接实现，不另拆计划或重复审批。

## 方案

采用插件控制流程：复用已存在的认证 status/shutdown API 和服务包 CLI start。因此旧的运行中服务也能被新版插件重启，不依赖新增服务端重启接口。不使用 PID 杀进程、不删除实例锁，也不将 shell 脚本作为跨平台实现。

## 行为

1. 新增用户命令 `/superagent restart` 和菜单“重启后台服务”。模型工具不暴露或允许 restart；加载、session_start 和普通查询不触发重启。同一插件会话防止重入，并避免与初始化向导交叉执行。
2. 仅操作已经确认绑定的本地实例。环境变量/SSH 隧道连接没有本地生命周期归属，先通过 `/superagent setup` 绑定本机实例；不把远端 shutdown 接成本机 start。
3. 读取并核对 binding、磁盘 instanceId/repository/port、客户端 endpoint，再认证读取服务状态。展示仓库、实例目录、Web 地址、paused 和忙碌 Worker 数；明确重启会结束 Router/Worker 及其子进程，未完成工作按已有恢复机制处理。
4. 用户确认前没有 shutdown/start。执行前先定位并检查可用的本地服务 CLI，避免停止后才发现无法启动；确认后再次检查实例身份。
5. 认证 shutdown 成功后，最多等待 30 秒，须同时观察实例锁消失和 loopback 端口关闭。API 已关闭但锁尚未释放时继续等待；超时、身份变化或停止失败均不启动第二个服务，不强杀或删锁。
6. 通过原生 Node execFile/参数数组调用现有 CLI start。启动后用新 Client 校验 protocol/instanceId，再报告成功。保留模型、来源、paused、绑定、凭据及工单数据，不自动恢复派单或提交任务。失败给出当前阶段、实例日志位置和恢复入口，不输出令牌。
7. 服务已离线且锁和端口均空闲时，明确提示将启动当前实例，确认后启动；认证失败、端口占用或未释放锁不能当作离线启动。
8. 旧版 Web 一键登录接口的提示直接指向 `/superagent restart`；用户重启后重新执行 `/superagent web`。本轮只对临时实例做重启测试，不操作用户业务实例。
