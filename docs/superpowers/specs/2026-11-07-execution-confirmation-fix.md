# 执行方式与确认提示修复

用户已批准直接修复。本轮不操作业务实例、仓库、模型或发布。

- 保留默认隔离工作树，增加管理员在 Web 工单内显式切换到原工作区的入口。只允许暂停派单后操作；预览实际目录、分支、HEAD 和脏状态，提交时校验预览指纹。停止旧 Worker 后切换，新会话重新读取原请求与指令，旧隔离文件保留。恢复派单仍独立确认。
- 原工作区执行记录按票持久化，不修改 core。逐仓锁保护多个服务的原目录执行；分支及仓库身份在启动、跟进和结果验证时检查；不 checkout/reset/清理用户改动。任务之间串行使用原目录。
- 用户回复后展示“补充已接收，待处理”，不假装配置已经生效。Worker 有未关闭问题时必须显式清除或提出新问题；禁止沿用已收到回复的原问题。Router 明确没有修改执行配置的模型工具。
- Web 全局待确认提示；Pi 已连接会话轮询待确认事项并按问题 ID 去重通知，不自动建立 SSH 连接或启动服务。关闭会话清理监听。
- 旧工单升级：由问题创建报告与后续人工输入恢复已接收状态，取消尚未发出的旧提问；不推断用户批准了执行配置，也不自动唤醒模型。旧停止 Effect 在切换事务内确认为已完成，不能释放刚取得的原目录租约。关闭服务等待在途切换结束。
- 回归验证：默认隔离不变；原目录/现有分支/预存删除保留；迁移确认与暂停门禁；陈旧预览、跨实例锁冲突、分支漂移拒绝；重启恢复；问题回复状态及提醒去重。使用临时仓库和假 Driver，不动业务数据。
