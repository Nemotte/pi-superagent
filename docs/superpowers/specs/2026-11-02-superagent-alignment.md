# Super-agent 语义校准

用户要求修正上一轮核对发现的设计差距；沿用直接实现、不另拆实施计划的要求。

## 边界

保留上游领域内核，修正 Pi 适配层，不改 `upstream/`。GitHub 继续作为当前外部来源，飞书延期。本轮不安装系统服务、不使用真实账号或付费模型。

## 协作与沟通

领域事件在同一事务中排入持久 relay / notice。人工跟进直接到 Worker，同时通知 Router，Router 对被持有消息只能按人的要求 stop。Worker 问题、结果和阻塞通知 Router；普通 progress 留在工单。结束、设置等背景 notice 不唤醒 Router。消息具有稳定投递 ID，重启可补投；同类有序，旧尝试不能覆盖新消息。

Router 增加受控 reply / note / status；Worker 增加 acknowledge / context follow / unrelated。所有操作仍由父进程校验角色与工单归属。接受时由模型提供具体 acknowledgement，可省略以遵循静默规则；移除固定确认和 ready/dropped 自动外发。问题通过结构化字段保存，由 Router 原样转达；dropped 默认静默。Outbox 按工单和对话保持前三次重试的顺序；持续失败升级为人工事项后，后续消息可继续。

## 模型上下文与指令

候选、工单、输入和报告使用有界卡片，保留可读取的指针。按对象分页读取 Trigger、Thread、Ticket 的输入/派工、报告和原始 GitHub 讨论；Worker 只能读自己工单及其关联消息。Router 可在仓库范围内只读文件以核对研判证据，路径不能逃出仓库。扩展工具不引入任意 HTTP 请求。

团队 communication / scope / delivery 使用文字配置。Worker 明确获得匹配规则正文、当前授权范围和团队指令。从本次修正起保存每次配置快照；正在进行的工单收到团队约定和规则更新，规则修改不直接撤销运行工单。团队及规则正文合计上限 32000 字符，根 AGENTS.md 上限 32000 字符；原配置超过预算时需缩减后启动。仅显式装配目标仓库内的 AGENTS.md，不发现个人扩展、个人技能或其他仓库指令。

## 策略

Source 接收范围与 Policy 准入分开。恢复只要求仍监听原 Thread，不要求仍接收该类全部消息。显式 follow-up 授权按上游复验；context-only 订阅不赋予 follow-up 强度。恢复 GitHub 每类事件的准入表与上游保守默认；机器人只能形成 inferred 候选。授权变化、规则变化和 proactive 模式变化分别通知。

## 人工入口

Web 默认显示待回答、待评审、受阻/失败及未完成评估。问题正文和可用动作直接显示；健康运行和原始 JSON 收入次级详情。未完成评估支持重新评估与忽略提示，保留工单/记录/诊断页。一次网络错误不升级为系统故障；Effects 或 GitHub 来源连续三次失败后进入待处理。每类最多展示 50 项，处理后补入后续事项。

## 验收

回归测试覆盖跟进 stop 的 Router 通知、报告通知与事务回滚/重开、静默规则、上下文边界与角色越权、准入/复验矩阵及 Outbox 顺序。真实 Pi SDK 离线集成验证 Router 收取报告后受控回复，背景通知不触发模型轮次；浏览器验证待人工事项和直接操作。
