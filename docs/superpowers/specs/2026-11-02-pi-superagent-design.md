# Pi Super-agent 设计与需求

状态：整体设计已获用户批准。用户要求文档化后直接实现，不生成拆解计划，也不增加实施前审批。2026-11-04 用户将实例范围扩展为一个应用的多个协作仓库，具体语义见 [多仓库工作区](2026-11-04-multi-repository-workspace.md)。

## 1. 产品范围

构建基于 Pi 的持续运行协作智能体。每个实例管理一个应用工作区（单个或多个协作 Git 仓库），由单个管理员自托管；当前团队成员通过 GitHub 协作；飞书按用户最新要求延期。首发目标包含独立服务、CLI、Web 管理面板和 Pi 插件，支持 Linux、macOS、Windows 原生运行。同一应用的前后端、微服务由一个实例协调；不同应用可使用独立实例，不引入多项目租户或多用户权限系统。

用户关闭 Pi、浏览器或 CLI 后，后台服务继续运行。实例之间的配置、凭据、数据库、会话、工作目录、端口及后台服务标识独立。

## 2. 发布边界

同一 npm workspace 仓库维护两个公开包：

- `@pi-superagent/server`：常驻服务、`pi-superagent` CLI、Web 静态资源和固定版本的 Pi SDK。包名是源码发布标识；实际 npm 发布前必须确认拥有该 scope。
- `@pi-superagent/extension`：Pi 命令、模型工具及状态显示，作为 Pi package 安装。宿主提供的 Pi、TypeBox 依赖只声明为 peer dependency，不打包第二份运行时。

版本从 `0.1.0-alpha.1` 开始。Node.js 基线为 24。服务 API 使用 `/api/v1`，连接时校验协议版本；不兼容版本明确拒绝。服务内部固定 Pi SDK `1.4.0`，不依赖全局 `pi` 的版本或个人 Pi 会话。

服务包包含编译好的 JavaScript、Web 静态资源和许可证。安装不得通过 postinstall 启动服务、修改系统设置、读取个人凭据或下载未验证二进制。发布前验证实际 npm tarball 在干净目录的安装和启动。

## 3. 组件与所有权

### 3.1 领域核心

移植 DeepSeek `dsh-superagent-prototype` 固定提交 `6337fc823ce20251c8de8085948165c81aaa701e` 的无宿主依赖 `src/core`，保留 MIT 归属及领域测试。`upstream/` 仅作为参考，不直接成为运行依赖。

保留 Trigger、Thread、Eval、Decision、Policy、Mandate、Ticket、Assignment、Subscription。Engine 是领域状态的唯一写入者；命令同步完成事务。端口只排入持久化动作，网络、子进程和模型调用在提交之后执行。

### 3.2 服务

服务拥有 SQLite、调度队列、来源轮询、回复发送、实例锁、子进程监督和 API。CLI、Web、Pi 插件都访问同一 API，不直接写领域数据库。实例锁在打开数据库前取得；重复启动不得触发第二次执行。

### 3.3 Pi 执行适配

Router 与 Worker 运行在服务管理的 Node 子进程中。子进程使用服务安装的 Pi SDK，父进程通过 IPC 向其发送命令并接收事件和工具请求。进程启动使用参数数组，不拼接用户输入为 shell 命令。

Router 只注册资源读取、路由、评估、状态查询和受控回复工具，不拥有 Bash 或写文件工具。Worker 只注册工作工具和绑定当前 Ticket 的报告、handback 等工具。父进程根据进程身份绑定 Ticket 和 Assignment，不接受 Worker 自报的其他工单身份。

每个 Ticket 有固定持久化 Session 和独立 Git worktree 工作区（多仓库时按原相对路径装配）；重试复用，只有 Assignment 更换。受管理会话通过显式 ResourceLoader 加载资源，不自动加载个人扩展、MCP 服务或提示词。Worker 可读取本仓库 AGENTS.md；Router 不加载代码实现指令。模型 provider/model 可分别配置。

Pi 的 `agent_end` 不作为自动处理结束信号；使用 `agent_settled`，再结合后台任务及结构化报告计算业务状态。原始自然语言输出不直接声明工单完成。

### 3.4 后台任务

长命令通过受管理任务启动、输出读取和取消工具执行，保存任务归属与有限输出。停止 Assignment 时清理其进程树。人工介入可以在后续模型步骤处理，不等待长命令完成。原型迁移期间不得把普通同步 Bash 宣称为已实现后台任务机制。

## 4. 状态与恢复

SQLite 保存领域对象、效果队列、回复收据、审计事件和配置版本；Pi Session JSONL 保存模型历史。数据库启用 WAL，文件采用只对运行账户可读写的默认权限。读取历史采用分页和大小上限。

效果队列以 kind/key 去重，保留 generation 和重试次数；执行完成只删除自己处理的版本。暂停或资源不足不累计失败。异常以指数退避重试，永久失败表现为可操作的工单或系统问题。

输入状态必须区分：排入持久队列、排入会话内存、进入会话历史，以及 Worker 后续报告/结束步骤。IPC 投递成功不代表模型已经读取。稳定 delivery id 与输入载荷一起存入 user message 的 JSON 信封；恢复时从 Session 文件核对，尚未进入历史的输入重新投递。确认前同步文件，不使用内存队列作为唯一来源。实现核对 Pi 1.4.0 后选择 user message：新 Session 的 setup/custom entries 在出现 user/assistant message 前可能尚未落盘，公开 message_end 回调也早于内部追加；因此确认必须检查持久文件，而非只监听事件。

启动时检查未结束 Assignment：中断执行通过 Engine 恢复；已等待人工或已 ready 的工作保持其状态。重启不能自动重做已经发生的 PR、评论等外部动作；渠道使用稳定幂等标记，Worker 接受恢复说明并检查外部事实。

业务数据库和 Session 文件不能组成一个跨存储原子事务，因此交付采用持久化重试、历史核对和幂等动作。进程和工作目录分离不等于 OS 沙箱。

## 5. 授权与自动化

- 管理 API 的人工派单拥有 explicit 强度。
- 外部来源按来源范围、允许名单和 bot 身份做确定性准入。
- 推断接单必须匹配启用规则并提供结构化方向与证据。
- `observe` 是默认模式，只记录 would-accept；`off` 关闭推断候选；`auto` 才创建主动工单。明确授权请求不受 observe/off 限制。
- Subscription 传递上下文，不扩大 Mandate。Worker 持有的人工跟进由 Worker 处理，超范围通过 handback 返回 Router。
- 人工停止撤销授权；全局暂停停止新派发、输入自动投递和回复发送，不假定其会打断当前模型步骤。
- Policy 变化使旧 Eval 失效并通知受影响工作；结束工单恢复前重新检查授权。

## 6. API 与安全

默认绑定 `127.0.0.1`；远程管理首版使用 SSH 隧道。服务生成高熵管理员令牌，配置文件不包含明文令牌。CLI 和 Pi 插件通过受保护令牌文件或环境变量读取，以 Bearer 访问 API。

Web 使用令牌交换 HttpOnly、SameSite=Strict cookie；登录后令牌不留在 localStorage。修改请求检查 Origin，并要求与登录会话绑定的 CSRF token。禁止宽泛 CORS；限制 Host，避免 DNS rebinding。静态资源设置 CSP，不使用外部 CDN，不渲染未经净化的 HTML。

所有写入 API 校验输入、大小和枚举；分页有硬上限。响应不返回访问令牌、模型凭据或任意主机文件。人工派单支持请求 ID 幂等性，重用同一 ID 不得更改原始请求。设置保存使用 revision 防止覆盖并发修改。

模型和来源凭据属于运行实例。支持管理员显式配置或导入，不能默认复制个人 Pi auth.json。日志不记录认证头和完整环境变量。

## 7. 三个用户入口

### CLI

提供初始化、前台 serve、健康诊断、状态、工单派发/详情/跟进/停止/重试、暂停、后台服务管理和备份。实例通过 `--state-dir` 选择。进程返回非零退出码表示错误，不把请求接受当作任务完成。

### Pi 插件

提供 `/superagent` 命令以及派单、列表、详情、跟进、停止、重试等模型工具。插件保持轻量，可选择一个服务实例；不把当前聊天会话当作后台 Router，也不在重载时终止后台任务。外部调用超时、未连接和协议不兼容以明确错误显示。

### Web

服务直接提供静态面板，包含：

- 总览：待人工事项、运行负载、系统问题。
- 工单：筛选、详情、授权、输入、Assignment、人工问题及操作。
- 事件与决策：Trigger、Thread、Decision、would-accept 记录。
- 来源：GitHub 连接配置及健康状态；飞书标记为延期。
- 设置：模型、并发、规则、暂停、提示词和版本。
- 运行诊断：有限日志、会话记录及版本信息。

首版可采用带增量游标的轮询，重连后以持久状态为准。无论从哪个入口操作，都应看到同样的状态。

## 8. 外部来源

2026-11-02 范围更新：用户要求暂缓飞书，先完成 GitHub，其余功能继续推进。当前 GitHub 接线适用于单仓库实例；多仓库实例先接本地手工任务，外部来源/PR 的仓库命名空间另行接入。GitHub 首轮使用 github.com REST 轮询，无需公网 webhook；使用实例专用机器账户 PAT（`github.token` 或显式 `PI_SUPERAGENT_GITHUB_TOKEN`），核验账号和仓库后读取。仓库及机器人身份一经配置不可在原实例更换，避免 Thread 和外发消息跨仓库串用。GitHub App 安装令牌和 Enterprise 端点另行接入。

各事件流从启用时开始，分页读取，失败保留持久游标，时间窗口重叠并以稳定事件 ID 去重。暂停期间继续收取事件，但不派单或发回复。PR 绑定必须是源 PR，或机器人在本仓库从该 Ticket 专用分支创建的 PR；禁止跨工单抢占。评论、review 回复携带实例相关幂等标记，重试先检查远端，限流遵守 Retry-After/重置时间。推断候选必须提交逐规则评估、明确方向及证据；observe 只记录 would_accept。

GitHub：Issue、PR、评论、review、CI 与合并/关闭事件；读取位置持久化，入站稳定 ID 去重，自身消息过滤。使用独立 agent 身份，消息发回原讨论。PR 的绑定和关闭通过 Engine 记录事实。

飞书（已按用户要求延期，不作为当前 GitHub 交付阻塞项）：允许范围内消息与话题跟进，身份和提及信息由适配器提取；回复回到原话题。网络失败不丢失读取位置。第三方 SDK 或 CLI 的支持平台须纳入发布验证。

两个来源不改变内核；新增来源实现同一边界。只有管理端可以生成 manual source 的管理员请求，外部来源不能伪造该身份。

## 9. 跨平台

业务层避免 POSIX-only 路径和 shell 假设。Git 操作通过 argv 调用，支持带空格和 Unicode 的路径。命令执行区分 POSIX shell 与 PowerShell；进程树停止分别实现 POSIX 进程组与 Windows 进程树语义。

后台托管适配 Linux systemd、macOS launchd 及 Windows 原生后台托管。每种适配器必须声明运行账户、启动时机、重启策略和卸载行为，不把 detach 子进程当作已完成系统服务托管。

验收包括真实三平台安装、启动、停止、重启、卸载及工作目录操作。当前机器上的模拟参数测试不代替 Windows/macOS 运行验证。

## 10. 测试与发布标准

- 上游领域规则回归测试。
- SQLite 事务回滚、重启、队列 generation、重复消息、失败退避。
- Pi IPC 的启动失败、取消、陈旧 Assignment 回调、输入确认和恢复。
- 真实临时 Git 仓库上的 worktree 创建和复用。
- API 身份验证、Origin/CSRF、输入校验、幂等及并发设置保存。
- Web 操作和 Pi 插件到同一个服务的契约测试。
- 在不调用付费模型的情况下，用独立进程测试执行适配协议；真实 Pi 集成另验证 SDK 导出、会话装配和工具注册。
- 三平台 CI 运行 build、typecheck、test 和打包安装冒烟测试。
- 模型实测、外部来源实测和后台托管实测单独记录证据；未验证项在发行说明中标注。

保留上游许可证和第三方归属。未经用户明确要求，不执行 npm publish、不创建远程仓库、不安装系统服务、不配置真实外部账号、不派发会产生费用的模型任务。
