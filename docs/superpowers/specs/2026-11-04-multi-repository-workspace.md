# 多仓库工作区

用户确认：一个 Super-agent 管理一个应用工作区，而非每个 Git 仓库各建实例。支持多个前端、后端主仓库及嵌套服务仓库组成的应用结构。本次按既有要求直接文档化和实现，不另拆计划或重复审批。

## 管理与执行

- 一个实例、一套 Router/工单/持久状态。一个 Ticket 的 Worker 可以跨已注册仓库完成同一需求，提交一份整体报告；不同 Ticket 沿用现有调度和 Router 协调。
- 不引入每仓库常驻 Agent，也不新增父子工单 DAG。延续隔离 worktree：每 Ticket 一个工作区目录，在其中按原相对路径装配各仓库的 worktree。原目录文件和未提交改动不复制、不覆盖。
- 保留既有单仓库配置兼容性。`repository` 继续作为实例根路径；新增可空 `workspace: {repositories: [{id, path}]}`。path 为根内规范化相对路径，允许 `.` 表示根本身为仓库，最多 32 个成员。工作区成员与根均为实例不可变身份的一部分。
- 管理员注册的成员集合是可用资源范围；每个工单的 Mandate 决定具体任务范围，不因可访问仓库而扩大任务授权。Worker 必须按任务修改相关仓库，分别交付 Git 改动与验证。
- 目前先接通本地 CLI/Web/Pi 手工任务闭环；多仓库实例不启用现有单仓库 GitHub 来源及 PR 工具。单仓库 GitHub 功能保留。多仓库外部事件/PR 需要按仓库命名空间接线，不能错误复用单仓库编号。

## 发现与初始化

只读发现有界递归目录中的 Git 根和 gitfile；遇到 Git 根后仅继续遍历其 gitlinks，不扫描整个源码树。未登记为 gitlink 的嵌套独立仓库可用 CLI `--member` 显式指定；跳过依赖、构建、隐藏目录及 symlink。显示 HEAD、dirty 和 gitlink 信息。无 HEAD、读取失败、缺失 gitlink 单独报告，不再统一误报“不是单一仓库”。最多扫描 3000 个目录、深度 8；达到预算明确报错，不静默返回部分结果。

CLI 增加 `discover --repo ROOT`、`init --workspace --repo ROOT [--member RELATIVE_PATH ...]`。不指定 member 时选取发现的可用成员；指定后校验其存在、唯一性和路径。插件向导支持工作区选择及成员勾选，默认 GitHub 关闭、单 Worker、暂停。实例数据目录须在工作区根之外，校验符号链接后的实际路径。绑定工作区根；从已注册仓库及其子目录重新进入 Pi，也能找到所属工作区实例。

## 基线、嵌套与恢复

首次启动工单前，宿主持久保存各成员的源路径、Git common-dir、当前 HEAD、dirty 提示、父仓库 gitlink 基线；之后才创建 worktree。部分创建失败时，重试沿用同一基线，不能因源目录 HEAD 前进而混用版本。

按父路径先于子路径装配。允许在父 worktree 的空 gitlink 目录中放置子 worktree；拒绝 symlink、非空占位、属于别的仓库或工单的目录、重复 common-dir，以及父仓库已追踪普通文件的路径冲突。缺失/未选择的 gitlink 保持空目录，不运行 submodule update、fetch、reset 或同步远端。

若已检出的子仓库 HEAD 与父仓库记录不一致，工作区使用各子仓库当前 HEAD 并显式记录差异，不把原有 gitlink 偏差误报为本次代码修改。缺失的模块不自动下载；`.gitmodules` 遗漏 gitlink 也不妨碍发现其他可用成员。

## 上下文与交付

- Router 获得工作区目录/仓库卡片，受控文件读取限制在所选仓库、路径连接目录和根级说明文件，不能通过父仓库读取未注册的嵌套仓库。
- Worker 的工作目录为装配后的 Ticket 工作区，获得成员路径、基线指针和任务范围。显式加载工作区根 AGENTS.md，以及各成员根 AGENTS.md/CLAUDE.md（AGENTS 优先），按路径说明适用范围；总预算 32000 字符。原个人目录/父级工作区指令不自动继承。
- 新增 workspace 上下文及管理 API，提供成员、持久基线、当前 HEAD 和有界改动摘要。上下文按页读取，禁止以文件增长扩大输出。
- Workspace 的 ready 报告提供 `repositories: [{id, summary, checks}]`；宿主核对成员 ID、不重复，以及实际发生改动的仓库均在报告中。checks 是执行者声明的验证证据，宿主另外保存 Git 状态，不能把目录可读当成构建通过。
- Web 展示实例工作区与工单分仓库状态/结果。CLI/Pi 可查看同一份 workspace 结果。各仓库分别提交，不自动跨仓库提交、推送、创建 PR 或合并。

## 验证与边界

保持领域内核不变。TDD 覆盖配置兼容/身份不可变、发现/缺失模块、嵌套 gitlink、源版本变化后的恢复、目录与仓库身份拒绝、读权限、分仓库报告、向导/连接继承；真实临时 Git 仓库验证跨前后端修改与统一完成。增加真实 Pi SDK 的本地脚本模型集成，不使用真实账号或修改业务项目。执行 verify、Web、tarball 和上游无差异检查。

工作区目录和环境隔离不替代 OS 沙箱。2026-11-04 验证：29 个文件、295 项测试，真实 SDK 的前端+嵌套后端修改/Node 一致性检查/重启闭环、安装包向导和 Chromium 工作区结果页面通过。曾在真实工作区只读验证已检出成员与缺失 gitlink 的发现，未创建业务实例或执行模型任务。

此次不新增原地执行模式，不安装系统服务，不创建真实业务实例或修改其 Git 元数据。实施本规范时产品根尚无 Git 仓库，产品代码在原目录修改，测试隔离在临时仓库中。
