# 一键 Web 登录与管理员令牌入口

后续 [插件内重启规范](2026-11-04-plugin-restart.md) 增加 `/superagent restart`，替代下文所述的手写重启命令；依然需要用户主动确认。

用户确认优化：保留常驻服务的管理认证，普通使用不要求寻找文件或输入长期令牌。沿用“文档化后直接实现”，不另拆计划或重复审批。

## 选择

- 仅增加令牌文件位置/复制按钮：能应急，普通登录仍需手动操作。
- 将长期令牌放进打开浏览器的 URL：会把长期管理权限带入地址、历史与进程参数，不采用。
- **采用短时、单次 Web 登录授权 + 私密令牌面板。** 沿用现有 HttpOnly/SameSite=Strict cookie 与 CSRF 校验。

## 行为与边界

1. 用户执行 `/superagent web` 或菜单“打开 Web（自动登录）”：插件先验证服务协议/实例身份，用已有 Bearer 凭据申请 60 秒有效的随机一次性 code。服务只在内存保存其 SHA-256、到期时间和申请所用 origin，最多 32 条，重启失效。仅 Bearer 管理客户端能申请，浏览器 cookie 不能生成新的登录授权。
2. 插件用自己的已验证 endpoint 构造 `/#login=CODE` 打开浏览器，绝不接受服务返回的任意跳转地址。短时 code 可随本次浏览器启动传递；长期 admin.token 不进入 URL、argv、通知、插件日志或模型工具返回。
3. Web 首先用 replaceState 清理 fragment，再通过同源 JSON POST 兑换 code。兑换要求严格 Origin、遵循 Host/限流/大小限制；成功立即消费，建立现有 cookie 会话；cookie 名包含实例 ID，避免同机不同端口互相覆盖登录状态。过期、重放、跨实例或跨 origin 均拒绝；错误不反射 code。刷新复用 cookie，退出不复用旧授权。
4. 自动打开失败：Pi 临时私密面板给出链接和复制操作，不通过 notify/聊天显示 code。过期后重新执行命令；不自动重试发放授权。`/superagent web url` 继续离线显示普通地址。模型工具的 `web` 仍只返回普通地址，不能生成授权、打开浏览器或读取令牌。
5. `/superagent token` / 菜单“管理员令牌（高级）”仅终端用户可用。先明确确认管理权限及剪贴板影响，再显示默认遮罩的私密面板，V 显示/隐藏、C 复制、Esc 关闭。值不放到编辑器、聊天或通知；关闭清理面板引用，60 秒后自动关闭。剪贴板工具通过 stdin 接收数据、无 shell、无密钥 argv，失败只显示通用提示。用户明确复制后保留其剪贴板，不后台覆盖。
6. 未绑定的跨项目环境连接需要确认目标后才能打开管理控制台/管理凭据。加载、session_start、普通 status/模型工具不发放授权、不打开浏览器。初始化继续显示普通地址及命令指引，不自动打开控制台。
7. 旧服务缺少新接口时清楚提示需要手动重启，并指向 `/superagent token` 作为当前可用入口。不自动停止/重启业务实例，不做用户 OAuth、付费探测或业务派单。新能力不修改 core、工作区配置或用户凭据文件。
