# Pi 插件实例引导

后续范围扩展：单仓库限制已由 [多仓库工作区规范](2026-11-04-multi-repository-workspace.md) 替代。以下记录引导初版；现入口同时支持工作区发现、成员勾选及成员目录连接继承。

用户希望在 Pi 中完成实例初始化，不再手工拼接 CLI、端口、认证和环境变量。沿用文档化后直接实现、不另写实施计划的要求。

## 交互

- `/superagent` 为统一入口：未连接时进入向导，已连接时显示状态/工单/提交任务/配置连接菜单；`/superagent setup` 随时进入向导。
- 会话启动只发现连接并显示状态，不创建目录、启动服务、登录或派单。
- 向导支持创建当前项目的本地实例，以及连接已有实例。Git 根目录作为项目身份；非 Git 目录允许选择直接子仓库或输入仓库路径。要求已有 HEAD，不自动 init、add、commit 或建立远端。
- 显示目标仓库、worktree 执行方式及未提交修改不进入 HEAD 的事实；用户确认后在 Git 工作树外创建私有实例目录、选择空闲 loopback 端口，默认 GitHub 关闭、单 Worker、暂停派单。
- 通过服务自带 SDK 的独立初始化进程列出模型，并在 Pi 对话框中完成实例专属 OAuth/API key 登录。密钥输入遮罩；回调、令牌不写聊天、不作为进程参数。不复制个人 Pi/gh 凭据。
- 可选择一次简短模型请求验证，明确说明使用模型额度。认证就绪与实际推理验证分别显示，验证失败保持暂停，不自动重试付费请求。
- 新实例配置成功后可确认恢复派单；连接既有实例不改模型、来源和暂停状态。中断后可继续配置，不覆盖既有实例或认证。

## 连接与边界

绑定保存在用户私有目录 `~/.pi-superagent/connections/`，按规范化项目路径散列为独立文件；只保存项目/仓库/实例路径和实例 ID，不在项目仓库写令牌或连接文件。相同项目再次进入可自动连接，其他项目不继承该绑定。

显式环境变量仍可连接既有实例；项目绑定优先，避免 shell 中旧 PI_SUPERAGENT_HOME 将新项目意外指向旧实例。裸命令显示实际仓库；来自另一项目的环境连接在首次写操作前必须由用户命令确认，确认仅绑定本次会话、当前项目、端点和实例 ID。模型工具不能自行确认；尚未确认时拒绝跨项目写入并提示 setup，保留 SSH 隧道连接方式。API 校验协议及预期实例身份。

插件通过服务的公开 bootstrap 入口定位 CLI 和认证子进程，使用 Node 参数数组执行，不嵌入第二份 SDK、不依赖当前仓库里的可执行文件。服务包缺失时给出安装/构建指引；也支持显式 PI_SUPERAGENT_SERVER 指定本机服务 CLI。仅用户操作向导才允许启动后台进程，不安装系统服务。

对比直接在插件中复刻模型认证和在启动时无提示初始化，选用服务 SDK 子进程加交互确认：保持固定 SDK、认证隔离和客户端边界，同时复用现有 CLI/API。

本次不改变单仓库/worktree 执行模型，不自动启用 GitHub，不添加 GitLab 原生渠道或特定项目的原地执行能力。

## 验证

TDD 覆盖项目发现、路径与实例绑定、跨项目防误派、取消/恢复、不覆盖实例、端口选择、CLI 参数、协议/身份检查及向导的完整顺序。认证 IPC 覆盖交互、取消、超时和秘密不进入输出。使用临时本地仓库、脚本模型及假认证交互验证向导→服务→插件；实际 OAuth 和终端交互验收与离线测试分别记录。保留全量 verify、浏览器与干净安装包验证，不操作既有测试实例或业务仓库。
